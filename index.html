TLSF · Two-Level Segregated Fit · 01

空闲块很多，
怎样快速找到合适的那一个？

TLSF（Two-Level Segregated Fit，两级分离适配）把空闲块按大小分为两级，以位图快速定位候选块。在固定配置下，分配与释放的块管理时间复杂度为 O(1)；结合按需切分和相邻空闲块合并，在保持快速响应的同时较好地控制内存碎片。它不会搬动仍在使用的块，因此不能消除所有外部碎片。下面可以逐步观察建池、查找、切分与合并过程。

01 / Caller-owned memory

先划定 TLSF 能管理的内存范围

TLSF 不向操作系统扩堆。应用先准备对齐且可写的内存，再初始化控制结构并加入一个或多个 pool；tlsf_destroy() 也不会替调用方释放这些区域。

pool 开销：64 位下 tlsf_pool_overhead() = 16 B，分布在池两端。起始空闲块的 size 字段占 8 B，用来记录块大小和状态；末尾 size=0、标记为已用的哨兵字段占 8 B，用来标记 pool 终点，避免遍历越界或跨界合并。此实现需要这两处字段；这里的 8 B 指 size 字段，不是整个 block_header_t。初始空闲块大小为 align_down(pool 字节数 − 16, 8)。对齐与调用：64 位配置的 tlsf_align_size() = 8 B。tlsf_create_with_pool() 不会把加入 pool 失败转换成创建失败；调用方需保证区域足够且对齐。场景输入：分配请求和块大小用于构造可复算的示例，不是 TLSF 固定常量；约束值取自源码。
01.1 / Source flow

TLSF 源码流程总览

从公开 API 顺着源码往下看：初始化怎样建立空闲分类，malloc 怎样找到并切分候选块，free 怎样合并后重新入链。

以下是 tlsf.c 的函数调用路径提要。后面的分配、位图和链表沙盘用于解释这些步骤；沙盘是页面中的教学模型，不是直接执行 C 源码。

01
初始化内存池控制结构先就绪，再加入 pool
tlsf_create_with_pool(mem, bytes)→tlsf_create(mem)→control_construct()
  1. tlsf_create 检查 control 内存对齐，再构造控制结构：空链表哨兵自环，FL / SL 位图清零，所有 blocks[FL][SL] 指向哨兵。
  2. 合并布局从 mem + tlsf_size() 开始加 pool；分离布局则由调用方另行调用 tlsf_add_pool(tlsf, pool_mem, pool_bytes)。
  3. tlsf_add_pool 检查 pool 对齐和大小，扣除两端开销并向下对齐，建立初始空闲块。
  4. 初始块先经 block_insert → mapping_insert → insert_free_block 入链并置位图；随后在池末建立零大小、标记为已用的哨兵。

注意：tlsf_create_with_pool 会调用 tlsf_add_pool，但不检查其返回值；调用方仍须保证内存区域有效、对齐且足够大。

回看内存布局 →
02
申请内存映射、查位图、摘块、准备返回
tlsf_malloc→block_locate_free→block_prepare_used
  1. adjust_request_size 将非零请求按对齐规整，并满足最小块要求；零请求或超出可管理上限会得到 0。
  2. mapping_search 得到搜索起点；search_suitable_block 先查当前 FL 中目标及更大的 SL，没命中再查更大的 FL。
  3. 位图定位到非空分类后，取该分类链表头；remove_free_block 摘除候选块，链表变空时清对应 SL 位，必要时清 FL 位。
  4. block_prepare_used 检查能否切分。能切分就由 block_split 产生余块并重新 block_insert；再标记已分配块并返回用户指针。

没有候选块：搜索返回空指针，tlsf_malloc 返回 NULL；余量放不下块头和最小块体时则整块分配，不制造过小余块。

03
释放内存标记、摘除邻块、合并、重新入链
tlsf_free→block_merge_prev / next→block_insert
  1. ptr == NULL 时直接返回；否则由 block_from_ptr 找到块头，并标记当前块为空闲。
  2. 若前一物理块空闲，先用 block_remove 从它原来的分类链表摘除，再吸收到当前块。
  3. 接着检查后一物理块；若也空闲，同样先摘链再合并。池末哨兵阻止越过 pool 边界。
  4. 最后只把合并后的块调用一次 block_insert，按合并后的实际大小重新映射，并更新位图。

关键点：释放不扫描整条空闲链表找邻居；块头状态用于定位物理邻块，分类链表只在摘除和回插时更新。

03.1 / Platform width & granularity

平台位数与 FL / SL 颗粒度计算

读取 03 两级划分中的池总大小，计算池内可用的 FL 档数；再输入参考大小定位 FL，并检查它是否落在池容量范围内。

这里的“位数”描述编译目标通常对应指针和 size_t 的宽度
64 位目标指针/size_t 通常为 8 B；对齐粒度 8 B；最小块 24 B；小块阈值 256 B（32 个 SL 档 × 每档 8 B）；FL 0–24，共 25 档。
32 位目标指针/size_t 通常为 4 B；对齐粒度 4 B；最小块 12 B；小块阈值 128 B（32 个 SL 档 × 每档 4 B）；FL 0–23，共 24 档。

源码常数关系：SL_INDEX_COUNT_LOG2 = 5，所以 SL_INDEX_COUNT = 2⁵ = 32；FL_INDEX_SHIFT = 5 + log₂(ALIGN)；SMALL_BLOCK_SIZE = 2^FL_INDEX_SHIFT = 32 × ALIGN；FL_INDEX_COUNT = FL_INDEX_MAX − FL_INDEX_SHIFT + 1（64 位的 FL_INDEX_MAX=32，32 位为 30）。

源码给出的是平台理论上可表示的 FL 上限；单个内存池实际能用到的 FL 子集还受最大连续空闲块限制。下方会读取 03 两级划分中的池大小，计算本例实际可覆盖的 FL 档数。

位数不等于位图宽度：本仓库的 fl_bitmap 和每个 sl_bitmap[fl] 使用 32 位 unsigned int；64 位配置只使用 FL 0–24，对应 SL 位图则使用 SL 0–31。

参考大小只用于按 TLSF 的大小映射规则定位 FL；它不是池子大小，也不代表一次分配请求。范围由 03 的池大小输入决定。

32 / 64 位切换只影响本计算器；本页其他交互示例仍按 64 位参数演示。

从阈值数到 FL 档数：
① 小块阈值：64 位下有 32 个 SL，每格最小按 8 B 对齐，所以小块范围宽度是 32 × 8 = 256 = 2⁸ B。这个阈值由 SL 数量和对齐粒度决定，不由池大小或输入的参考大小决定。
② FL 0：负责 [0, 256) B；它下面的 32 个 SL 各覆盖 8 B。这样每格不会细到小于 8 B 的对齐粒度。
③ 大块 FL：从 256 B 开始按 2 的幂划范围：FL 1 是 [2⁸, 2⁹) B，FL 2 是 [2⁹, 2¹⁰) B，依此类推，FL 24 是 [2³¹, 2³²) B；每升一级，范围扩大 2 倍。
④ 为什么总数公式要 +1：FL_INDEX_MAX − FL_INDEX_SHIFT = 32 − 8 = 24 数出 FL 1 到 FL 24 这 24 个大块档；+1 把专门处理小块的 FL 0 也计入，所以总共 25 档（FL 0–24）。32 位下阈值是 32 × 4 = 128 = 2⁷ B，总共 24 档（FL 0–23）。

08 / TLSF 的优势与代价

为什么选 TLSF：让分配开销可预期

核心价值不是“任何情况下都最快”，而是让 malloc/free 的块管理路径不随池内块数增长，并在可控内存池中复用不同大小的块。

有界查找

分配与释放均为 O(1)

分配请求映射到 FL/SL 后，由固定宽度位图定位候选分类，不逐个扫描空闲块；释放只检查直接相邻块并更新链表。因此块管理步骤不随池内块数增长。

请求大小→FL / SL→位图→链表头
mapping_search() · search_suitable_block()
碎片控制

切分与合并兼顾速度和空间

分配时按需切分空闲块，释放时合并相邻空闲块，减少小空洞长期分散。大小分类让查找保持有界，但它不是精确 best-fit；TLSF 不会搬动仍在使用的块，无法消除所有外部碎片。

空闲块→按需切分+相邻合并→可复用空间
block_split() · block_merge_prev() · block_merge_next()
内存可控

内存池由调用方提供

应用决定 TLSF 管理哪段内存；可以初始化一个 pool，也可以把多个区域加入同一管理器。分配器本身不会向操作系统扩堆。

应用内存区→control_t+pool

适用场景对分配延迟可预测、内存边界明确有要求的系统，例如嵌入式或实时工作负载。这里的 O(1) 指分配器块管理步骤，不包含调度、锁、缓存未命中等整机耗时。
必须一起考虑的代价64 位示例中 control_t 为 6536 B，每个已分配块头开销为 8 B，每个 pool 开销为 16 B；小内存池里这部分占比可能明显。分类查找不是精确 best-fit；TLSF 不搬动仍存活对象，因此不能消除所有外部碎片。具体开销可分别查询 tlsf_size()、tlsf_alloc_overhead()、tlsf_pool_overhead()。

这些优势在实现中对应的六条规则

01

同一块有两种关系

pool 中的物理顺序用来找左右邻块；空闲块按 FL/SL 放入大小分类链表。一个是地址关系，一个是查找关系，不能混为一条链。

02

按大小划分候选

小于 256 B 的块按 8 B 步长进入 FL 0；更大的块按 2 的幂分 FL，再把每个范围均分为 32 个 SL。

03

搜索映射向上取整

大块请求先向上取整到分类边界，确保候选块不会比请求小。结果是有界查找，但不保证选出全局最小的可用块。

04

只在余量可表示时切分

余量必须容纳新块头和至少 24 B 的最小块体；不足时整块交给调用方，避免制造无法再次管理的碎片。

05

释放时先摘链、再合并

如果左右邻块空闲，先从原分类链表移除，再吸收相邻块头，最后只把合并结果映射并插入一次。

06

快速不等于没有边界

malloc/free 元数据操作不随块数增长；遍历与检查会扫描，realloc 搬迁要复制数据。TLSF 不扩堆，也不自动搬动活块消除外部碎片。

09 / Extending the FL range

增大 FL_INDEX_MAX：需要一起检查哪些源码

FL_INDEX_MAX 不只是一个“最大块大小”数字。改它会扩大分类表，也会碰到位图宽度、映射边界、池大小校验和控制结构占用。

先看当前配置的关系

64 位配置中 FL_INDEX_SHIFT = 8，所以 FL_INDEX_COUNT = FL_INDEX_MAX − 8 + 1。当前 FL_INDEX_MAX = 32 得到 25 个 FL（FL 0–24）；block_size_max = 2^32 B 是映射上界。增加这个值会增加可表达的大小级别，也会让 control_t 变大。

关键结论：通常不需要重写 tlsf_malloc() / tlsf_free() 的主体，但必须检查它们调用的映射、位图查找和链表插入/摘除代码。只改常量并不能保证新上限可用。

01

配置常量与 FL 档数

tlsf_private 中的平台分支定义 FL_INDEX_MAX；FL_INDEX_SHIFT 与 FL_INDEX_COUNT 决定小块阈值和数组需要多少行。改大后要确认目标平台的 size_t 能表示 2^FL_INDEX_MAX，且 FL 编号没有超出表格。

02

大小到 FL / SL 的映射

tlsf_fls_sizet() 取得大小的最高置位；mapping_insert() 把空闲块映射到数组下标；mapping_search() 为申请向上取整。检查新范围内的移位、整数宽度和加法溢出，尤其是当前用整数字面量 1 << ... 计算舍入量的表达式；编译期 size_t / int 宽度断言也要与目标上限相符。

03

控制结构及其占用

control_t 按 FL_INDEX_COUNT 建立 SL 位图数组和链表头二维数组；control_construct() 也按这个数量初始化。档数增加会让控制结构增大；64 位下每增加一档，位图和 32 个链表头约增加 260 B（另计结构体对齐）。调用方必须按新的 tlsf_size() 提供控制结构空间。

04

一级位图的宽度与末位搜索

当前 fl_bitmap 是 32 位 unsigned int，最多表示 FL 0–31。按 64 位配置公式，FL_INDEX_MAX = 39 时会用满 32 行；再增大就必须扩宽或拆分一级位图，并改对应的置位扫描函数。即使仍在 32 位内，也要处理 FL 31 上 ~0U << (fl + 1) 可能移位 32 位的边界情况。

05

位图置位、清位与一致性检查

插入/摘除分类时会用 1U << fl 更新一级位图；搜索用它找下一个非空 FL；tlsf_check() 用它核对位图和链表。扩大范围后要统一检查这些掩码、循环边界和位扫描；若位图超过 32 位，不能只把字段类型改大，还要配套更宽的扫描实现。

06

最大块、内存池边界与公开接口

block_size_max、adjust_request_size()、tlsf_block_size_max() 和 tlsf_add_pool() 必须采用一致的上界。当前申请调整要求大小严格小于 block_size_max，但加池检查只拒绝大于它的块；恰好等于上界时可能映射到数组末尾之外，需要明确修正。错误提示中的 unsigned int 格式也可能显示不出扩大的字节数。
